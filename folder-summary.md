# BitStamp_Interview folder: summary (read 2026-10-25)

Local path: `D:\Projects\BitStamp_Interview`. npm package `sportsbook-feed-research` (Node >=24, deps: `ws`, optional `playwright`). Run with `node --use-system-ca` because system Node 20 has CA trust problems. Do not disable TLS verification.

## What it is
A research kit for a Betstamp take-home. It investigates how to get live **DraftKings Ontario** and **FanDuel Ontario** NFL odds (moneyline/spread/total) for an odds-comparison app. **It is not the deployed comparison app the take-home asks for.** The take-home document itself is not in the folder. No login, CAPTCHA solving, proxies or location spoofing were used.

## Main conclusion
Use a REST snapshot for discovery and bootstrap, plus one persistent WebSocket per book for price changes. Architecture: one collector per book → normalized in-memory cache → SSE/WebSocket deltas to browsers (no upstream connection per viewer). On reconnect: subscribe and buffer, take a fresh snapshot, then reconcile. Use capped exponential backoff with jitter, mark a book stale while it is down, and never pick a suspended or stale price as best. Match events across books by canonical teams, home/away and start time, and compare prices only at an identical market/period/side/line.

## DraftKings (dkcaon / CA-ON-SB, NFL leagueId 88808)
- WS: `wss://sportsbook-ws-ca-on.draftkings.com/websocket?format=json` sends a JSON-RPC `subscribe` with entity `events`, `initialData:false`, empty `jwt`. Updates arrive at `message.data.data.{add,change,remove}.{events,markets,selections}`. Merge partial changes by ID. An unknown ID means resync. msgpack exists but was not benchmarked.
- Snapshot: `https://sportsbook-nash.draftkings.com/api/sportscontent/dkcaon/v1/leagues/88808`. The **Oct 25 fix**: the Akamai 403s were caused by the User-Agent. A current Chrome 156 UA alone returns 200; the default Node UA, a Chrome 142 UA and no headers all return 403. No cookies are needed. Implemented in `dk-http.cjs` (`DK_USER_AGENT` overrides the UA). The response has `subscriptionPartials`, which feed the WS subscription filters, and `Cache-Control: public,max-age=1`. The browser now uses a CMS `controldata/league/leagueSubcategory/v1/markets` route, but the legacy route still works.
- Race (2 min, 1 s polling, same process, `performance.now()`): 26 events, 78 markets, 156 selections; 120 polls, 0 errors, 19 WS frames, 6 matched changes. WS was first on 5, polling on 1. Median WS lead 2,214.5 ms. All 6 changes came from one live game (PIT @ NO), so this is not a general claim.

## FanDuel (Ontario)
- Discovery: `sbapi.on.sportsbook.fanduel.ca/api/content-managed-page?page=CUSTOM&customPageId=nfl&includePrices=true&_ak=FhMFpcPWXMeyZxOx`. Market types: `MONEY_LINE`, `MATCH_HANDICAP_(2-WAY)`, `TOTAL_POINTS_(OVER/UNDER)`. Response is cached with max-age=30 and swr=60, so use it for structure only. Found 27 events, 81 markets, 162 selections. Live board: `/api/in-play`.
- Push: AppSync `wss://pir.on.sportsbook.fanduel.ca/graphql/realtime` with the `graphql-ws` subprotocol. Sequence is `connection_init` → `start` with `subscription OnUpdateMarketPrice($ids)`. Auth is the public `aws_appsync_clientId` scraped from `captures/fd-main.js`. GraphQL snapshot: POST `pir…/graphql` `GetMarketPrices`.
- Poll fallback: SMP `smp.on.sportsbook.fanduel.ca/.../getMarketPrices?priceHistory=0` with `X-Application` set to the app key. Returns no-cache. The frontend polls every 5 s with batches of 70.
- Race (2 min, 18 live college-football markets, 5 s polling): 76 matched transitions, **WS first on all 76**, median lead 1,803.5 ms, p95 4,079.6 ms. An earlier 90 s run: WS first 65 times, polling first 8 times. Sanity check: 57/59 pushed states matched a polled state. Differences: the socket rounds decimal odds to 3 places, intermediate prices can fall between polls, and suspension/omission are represented differently. No live NFL movement has been observed on FD yet.

## Go port (added 2026-10-25)
The DraftKings and FanDuel REST + WebSocket clients are ported to Go in `go/` (module `sportsbookfeed`, dependency `gorilla/websocket`). Build with the workspace-local `GOPATH`/`GOMODCACHE`/`GOCACHE` shown in `go/README.md`; binary is `go/oddsfeed.exe`. Commands: `dk-snapshot`, `dk-ws` (`-mode probe|partials`), `fd-discover`, `fd-rest`, `fd-ws` (`-live`), `verify`, and `soak` (long-running keepalive + REST reconciliation). It reads `captures/fd-main.js` for the rotating AppSync client id/GraphQL documents and writes to `out/`. Live parity on Oct 25: DK 26/78/156 with identical entity IDs and partial keys; FD normalized rows 156/156 identical to `extract-fd-nfl.cjs`; FD GraphQL (2,671 B) and SMP (3,477 B) raw bodies byte-identical; FD AppSync received live data frames. One difference: the SMP POST returns 500 with Go's default User-Agent, so the Go client sends a browser UA. `soak -duration 1h` (Oct 25, 16:20-17:20Z, spanning NFL kickoff) held 99.94% DK / 99.93% FD uptime with 0 REST errors and 120 reconciliations per book; DraftKings closed its socket at exactly 30 min (`1006`) and the harness reconnected in 1.6 s, while FanDuel resubscribed twice on discovery market-set changes. Output is 57 MB in `out/soak-1h/`; see `go/SOAK-1H-RESULTS.md`. Not ported: the race analyzers, Playwright capture, and diagnostics; a production always-on collector and browser fanout are still open, though the soak harness now covers reconnect/resync/reconciliation.

## Normalization prototype (separate workstream, added 2026-10-25)
`normalizer/` is a separate Go module (no dependency on the feed clients) that replays raw DK/FD payloads through a canonical model and measures it. Design: atomic **quote keys** (`sport | event-scope | family | period | subject | stat | comparator | line | outcome`), event scope built from sorted team IDs + UTC date, per-book rule packs, team/player registries, and explicit `comparable` vs `unknown` states. It measures event/board overlap separately from normalization quality, then quote identity (line ignored), exact-line coverage, line mismatches, price dispersion, taxonomy coverage and dangling records. Real-data result: NFL pregame **25/25 events and 100% quote identity**, **124/150 exact-line**; live **12/12 and 100% identity**, **58/72 exact-line**; the 26/14 misses are real half-point line differences. NBA boards only overlapped on **7 of 18 games** (DK had 5 Christmas games, FD had 10 suffix-named games), but conditional on the 7 shared games identity was **100%** and exact-line **34/42 (81.0%)**. Taxonomy: all sampled markets get a family; high-confidence coverage FD NFL 81.7%, NBA 32.6%, NHL 54.9%; futures/awards are low-confidence and non-comparable. NFL alts are **far**: exact cross-book alt identity in sampled sets was **0** because DK exposes 1st-half/quarter props where FD exposes full-game props (24 anytime-TD players overlap but different period). NBA props were initially missed because FanDuel’s league page omits them; the event-level MGA MARKET feed returns 268 markets for Pistons@76ers, including the same 34 full-game props/10 players as DK, with 68 common outcomes, 58 exact-line (85.3%) and a median fair-probability gap of 1.38% (max 5.79%). Polymarket is now in the ring too: `go/internal/pm` reads Gamma events and CLOB market WebSocket, while `normalizer/internal/adapters/pm.go` maps binary outcome tokens to canonical quotes. Gamma returned 100 open NBA events / 4,760 markets and 62 NFL / 14,480; one Lakers–Jazz game normalized 926 quotes (6 main / 920 alt, 283 props) with 6/6 mainline identities and 90 exact-line matches against combined DK main+alt; Packers–Lions normalized 892 quotes with 6/6 identities and 74 exact-line matches. Polymarket prices are probabilities and need de-vigging before fair comparison with sportsbook American odds. Direct price decomposition: only 17–19% of mainline quotes differ by line; on identical lines the median fair-probability gap is ~0.9–1.1% (98%/83%/100% within 2%), pregame overrounds are identical and best-price outcomes symmetric, so most price differences are vig/rounding, not different values; live DK has a wider margin (6.71% vs 5.91%). One NFL “favorite flip” (DK Jets/Raiders) conflicts with DK’s own moneyline, indicating stale DK data; the NBA Pistons/76ers flip is internally consistent and a real disagreement. DK broad partial cache: **590/592 selections without marketId** (dangling, not guessed). Full design and report: `normalizer/DESIGN.md`, `normalizer/REPORT.md`. Not integrated into an app; next blockers are player/team registries and period/settlement alignment before scaling to 10–100 books.

## Open gaps
No actual app (collector service, normalization integration, browser UI). The normalization prototype needs player/team registries, line-grid policy and settlement/period rules before 10–100-book use. Polymarket needs a de-vig/fair-probability comparator and current-slate filtering. No production reconnect/resync beyond the soak harness, schema validation or monitoring. DK subscriptions still need narrowing to main markets. There is no end-to-end latency measurement. Public keys and UAs will rotate.
